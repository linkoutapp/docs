# Action policy

Every mutation is disabled by default.

:::note Release availability
Atomic reservations require a release containing the security-hardening change. The published `linkout-scraper@2.0.0` artifact predates that change; installing it alone does not enable these protections.
:::

| Operation | Default enabled | Default admitted-attempt limit |
| --- | ---: | ---: |
| `connect` | No | 10 |
| `message` | No | 20 |
| `like` | No | 30 |
| `endorse` | No | 10 |

The default local operating window is 09:00 through 17:59. The end hour, `18`, is exclusive.

Before an action begins, `createActionPolicy().begin()` checks in this order:

1. `confirm` is the boolean `true`.
2. The operation exists in the policy and has `enabled: true`.
3. The current local hour is within `operatingHours`.
4. When both `page` and a `detectState` function exist, page-state detection does not return `stop: true`.
5. The ledger atomically reserves an attempt for that operation and local calendar date, within `dailyLimit`.

`createActionPolicy().begin()` requires the literal boolean `true`; strings such as `"false"` do not authorize work. Pass `confirm: true` only after a person has reviewed and confirmed the exact action.

A rejected gate records the rejection and throws one of these stable error codes:

| Code | Meaning |
| --- | --- |
| `CONFIRMATION_REQUIRED` | Explicit confirmation was absent |
| `OPERATION_DISABLED` | The operation is missing or disabled |
| `OUTSIDE_OPERATING_HOURS` | The local hour is outside the configured window |
| `DAILY_LIMIT_REACHED` | The admitted-attempt budget has reached the configured limit |
| `PAGE_STATE_STOP` | Page-state detection requires the action to stop |
| `ATOMIC_LEDGER_REQUIRED` | A custom ledger lacks atomic reservations |
| `INVALID_DAILY_LIMIT` | The limit is not a non-negative safe integer |
| `LEDGER_BUSY` | Another process or a stale lock prevents admission |

A successful `begin()` writes one `outcome: "reserved"` entry with an `actionId` before browser interaction. Every reservation consumes one slot, including pending or failed work: a browser error can occur after an action was sent. A later success with that action ID does not consume another slot. Older success entries without an action ID also count. Gate rejections do not reserve work. `countSuccessful()` still reports only successful outcomes.

A standard mutation service records `outcome: "failed"` if an admitted interaction fails. Failures before `begin()` are outside the policy ledger.

## Ledger boundary

By default, each policy creates an in-memory ledger. Standard mutation services create a fresh default policy, and therefore a fresh ledger, for every service call when neither `data.actionPolicy` nor `cdp.actionPolicy` is supplied. Counts do not carry between those calls, even inside one process.

Create one policy and inject it into each related call to share its count:

```js
const Linkout = require("linkout-scraper");

const actionPolicy = Linkout.tools.createActionPolicy({
  config: {
    operatingHours: {start: 9, end: 18},
    operations: {
      connect: {enabled: true, dailyLimit: 10}
    }
  }
});

await Linkout.services.connect(page, {actionPolicy}, {
  url: "https://www.linkedin.com/in/example/",
  message: "Hello.",
  confirm: true
});
```

The shared ledger still resets when that policy or Node.js process is replaced. The default memory ledger is therefore not a durable daily safety control or an account-protection mechanism.

Each sanitized entry contains `timestamp`, `operation`, `target`, `outcome`, `errorCode`, and, when supplied, `localDate` and `actionId`. A target is retained only as the origin and path of an HTTPS `www.linkedin.com` URL; query strings and fragments are removed, and other targets become an empty string. Other supplied fields are discarded. The ledger does not retain page contents, credentials, cookies, session tokens, message or connection-note bodies, or unrelated profile data.


For cross-process or restart-safe admission, inject `createLedger({stateDirectory})` from `linkout-scraper/lib/policy/ledger`. All writers for an account must share that private directory and timezone. Custom ledgers must provide atomic `reserve(entry, limit)`. The file ledger holds an exclusive `.lock` while it checks and reserves capacity; a competing process fails closed with `LEDGER_BUSY`.

After a crash, stop all writers before removing a stale `.lock`. Keep the ledger itself so existing reservations continue to count. No automatic timeout steals a live writer's lock.

## Page-state boundary

The four standard mutation services pass `page` to `begin()`, and a normally created policy uses the default page-state detector. Injecting a policy can replace `detectState`, including with a non-function that skips the policy's page check.

Mutation click and typing helpers also check page state by default, but their interaction options are injectable. These are useful default stop checks, not unbypassable guarantees.

:::warning Platform risk
Confirmation, hours, counts, and stop states reduce accidental execution. They do not guarantee account safety or compliance with LinkedIn rules.
:::
